1. PURPOSE
--------------------------------------------------------------------------------

Native Android application that browses and downloads research papers from
sci-hub mirrors. On first launch the user picks a storage folder; the app
auto-creates /track and /papers subfolders, fetches random papers from
CrossRef, accepts a DOI or URL search, fetches sci-hub's related-paper
list, solves the altcha proof-of-work captcha transparently, downloads
PDFs with HTTP Range resumable transfers, and tracks which DOIs are
already downloaded in rotating 100-paper JSON files.

3. BUILD PIPELINE
--------------------------------------------------------------------------------

Toolchain locations (Debian 13):
  JAVA_HOME     /home/z/apk-build/jdk-21           (Adoptium Temurin 21)
  ANDROID_HOME  /home/z/apk-build/android-sdk
  BUILD_TOOLS   $ANDROID_HOME/build-tools/34.0.0   (aapt2, zipalign, apksigner)
  DX_TOOLS      $ANDROID_HOME/build-tools/30.0.3   (dx — NOT d8)
  PLATFORM      $ANDROID_HOME/platforms/android-30/android.jar

Critical rules followed by build.sh:
  (1) javac -source 8 -target 8 -Xlint:-options
      Android runtime cannot consume JDK 21 bytecode.
  (2) dx from build-tools/30.0.3, never d8 from 34.0.0
      d8 34.0.0 throws NullPointerException on javac-21 Java-8 output.
  (3) DEX injected with `zip -u -0` (STORE method)
      Unzip+rezip corrupts binary resources.
  (4) zipalign before apksigner
      Otherwise install fails with "problem parsing the package".

Seven-step pipeline:
  1.  javac -source 8 -target 8 → build/classes/*.class
  2.  $DX_TOOLS/dx --dex → build/classes.dex
  3.  $BUILD_TOOLS/aapt2 compile --dir res → build/res/compiled_res.flata
  4.  $BUILD_TOOLS/aapt2 link -o build/app-unsigned.apk --manifest ... -R ...
  5.  zip -u -0 build/app-unsigned.apk classes.dex
  6.  $BUILD_TOOLS/zipalign -f 4 → build/app-aligned.apk
  7.  $JAVA_HOME/bin/java -jar $BUILD_TOOLS/lib/apksigner.jar sign
        --ks build/debug.keystore (RSA 2048, validity 10000 days,
        storepass=android, alias=mykey)

Rebuild command:
  cd /home/z/my-project/android-app && ./build.sh

5. STORAGE LAYOUT
--------------------------------------------------------------------------------

User-chosen root folder (persisted in SharedPreferences key "root_folder").
On Android 11+ the user grants MANAGE_EXTERNAL_STORAGE then picks a tree
via ACTION_OPEN_DOCUMENT_TREE; the SAF URI is converted back to a
filesystem path so plain java.io.File operations work.

Subfolders created automatically by TrackerStore.ensureSubdirs():

  <root>/
  ├── track/
  │   ├── papers001.json    (DOIs 1-100)
  │   ├── papers002.json    (DOIs 101-200)
  │   ├── papers003.json    (DOIs 201-300)
  │   └── ...
  └── papers/
      ├── 10.1146_annurev.soc.29.010202.100047.pdf
      ├── 10.1146_annurev.psych.60.110707.163459.pdf
      ├── 10.1146_annurev.psych.60.110707.163459.pdf.partial
      │   (in-flight or interrupted download — resumable)
      └── ...

Track file format (papersNNN.json):
  {
    "papers": [
      {
        "doi":       "10.1146/annurev.soc.29.010202.100047",
        "title":     "Relationships in Adolescence",
        "filename":  "10.1146_annurev.soc.29.010202.100047.pdf",
        "added_at":  1792040882000
      },
      ...
    ]
  }

Rotation rule: when papersNNN.json contains 100 entries, the next write
creates papers(NNN+1).json. TrackerStore.currentTrackFile() returns the
first existing file with < 100 entries, or creates the next index.

Lookup is O(N) across all track files — at most a few thousand entries
total, so the scan is sub-millisecond on device.

7. NETWORK FLOW — CAPTCHA SOLVER
--------------------------------------------------------------------------------

Class: com.papers.app.SciHubClient

Constants:
  UA = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
        (KHTML, like Gecko) Chrome/120.0 Safari/537.36"

7.1  resolvePdf(doi)  →  pdfUrl

   Step 1.  GET  <base>/<doi>
            Headers: User-Agent, Accept: text/html
            Cookies captured: __ddg1_, __ddg8_, __ddg9_, __ddg10_,
                              PHPSESSID, session, refresh
            If the response is NOT a captcha interstitial (page lacks
            "/captcha/challenge"), the page already contains the PDF
            link and we skip to step 7.

   Step 2.  Extract challenge ID from page HTML:
              regex /captcha/challenge/(\d+)

   Step 3.  GET  <base>/captcha/challenge/<id>
            Headers: User-Agent, Cookie (from step 1), Accept: application/json
            Response JSON:
              {
                "algorithm": "SHA-256",
                "challenge": "<64-hex>",
                "maxNumber": 200000,
                "salt":      "<salt>?expires=<ts>&",
                "signature": "<64-hex>"
              }

   Step 4.  Solve proof-of-work:
            For n in [0 .. maxNumber]:
              hash = SHA-256(salt + str(n))
              if hash.startsWith(challenge):  solution = n
            Typical solve time on device: 50-200 ms.

   Step 5.  Build altcha payload (base64-encoded JSON):
              {
                "algorithm": "SHA-256",
                "challenge": "<hash>",
                "number":    n,
                "salt":      "<salt>",
                "signature": "<sig>",
                "test":      false,
                "took":      <ms>
              }

   Step 6.  POST <base>/captcha/solution/<id>
            Headers: User-Agent, Content-Type: application/json,
                     Accept: application/json, Cookie (merged),
                     Referer: <base>/<doi>, Origin: <base>
            Body:   { "captcha": "<base64-payload>" }
            Expected response: { "success": true }

   Step 7.  GET  <base>/<doi>  (reload with verified session cookie)
            Headers: User-Agent, Cookie, Referer: <base>/<doi>,
                     Accept: text/html
            Extract PDF URL from response HTML (see §7.4).

7.2  fetchRelated(doi)  →  List<Paper>

   GET <base>/similar/<doi>
   If response contains "/captcha/challenge":
     Solve captcha via steps 2-6 above (using the similar URL as Referer)
     Retry GET on /similar/<doi> with verified cookie.
   Parse the <a class="article"> blocks (see §7.5).
   Returns up to ~187 related papers.

7.3  CrossRef calls (no captcha)

   lookupDoi(doi):
     GET https://api.crossref.org/works/<urlencoded doi>
     Returns: Paper with doi, title, journal, year, authors, abstract.

   fetchRandom(n):
     GET https://api.crossref.org/works?sample=<n>
         &select=DOI,title,author,container-title,published,abstract,type,publisher
     cache: no-store  (each call returns a different random batch)
     n capped at 100 by CrossRef's sample endpoint.

7.4  PDF URL extraction (in order of preference)
     1.  class="download"><a href="...">
     2.  <meta name="citation_pdf_url" content="...">
     3.  /storage/[^"'\s<>]+\.pdf
     Relative URLs converted to absolute using <base>.

7.5  Similar-page article block parser

   Regex: <a[^>]*class\s*=\s*"article"[^>]*>([\s\S]*?)</a>
   Per block, extract:
     href        → DOI  (strip leading "/")
     <div class="title">      → title
     <span class="journal">   → journal
     <span class="year">      → year
     <div class="abstract">   → abstract
   HTML stripped via regex <[^>]+> then entity-decoded.

7.6  DOI input parser (SciHubClient.parseDoiInput)

   Pattern: \b10\.\d{4,9}/[^\s"<>]+
   Accepts bare DOI, https://doi.org/<doi>,
   https://sci-hub.su/<doi>, or any URL containing a DOI.
   Trailing punctuation [.,;)] stripped.

8. DOWNLOAD PIPELINE — RESUMABLE
--------------------------------------------------------------------------------

Class: com.papers.app.Downloader
Executor: Executors.newFixedThreadPool(2)

8.1  download(doi, title, pdfUrl)

   Path: <root>/papers/<safeFilename(doi)>.pdf
   Partial: <root>/papers/<safeFilename(doi)>.pdf.partial
   safeFilename: doi.replaceAll("[^A-Za-z0-9._-]", "_")

   If target .pdf exists:
     Already complete — call tracker.markDownloaded() and return.
   Else:
     startPos = (partial exists) ? partial.length() : 0
     Open HttpURLConnection:
       Request: GET <pdfUrl>
       Headers:
         User-Agent: <UA>
         Accept: */*
         Range: bytes=<startPos>-     (only if startPos > 0)
       setInstanceFollowRedirects(true)
       connectTimeout 15000, readTimeout 60000

     Accept HTTP 200 (server ignored Range, restart from 0)
            or HTTP 206 (server honored Range, resume)

     Open RandomAccessFile on .partial, seek(startPos)
     Loop: read 8192-byte chunks, write to RAF
           every 250 ms call listener.onProgress(doi, downloaded, total)
     On EOF: raf.getFD().sync(), close streams
     Rename .partial → .pdf  (fallback: copy if rename fails)
     tracker.markDownloaded(doi, title, target.getName())

8.2  ProgressListener callbacks

   onProgress(doi, downloaded, total)
     Updates per-card label showing e.g. "1.2 MB / 3.4 MB"
   onComplete(doi, savedFile)
     Adds doi to downloadedDois set, refreshes adapters, shows toast
   onError(doi, message)
     Adds doi to failedDois set, refreshes adapters, shows toast

8.3  Retrying a paused download

   Downloader.listPausedDownloads() returns all *.pdf.partial files.
   On retry the user may either:
     - Paste the PDF URL directly (if known), OR
     - Leave blank and the app re-resolves via SciHubClient.resolvePdf(doi)
   The existing .partial file's byte position is reused as the Range
   header start, so the download resumes from where it stopped.

10. FIRST-LAUNCH FLOW
--------------------------------------------------------------------------------

  onCreate() checks tracker.isFolderChosen()
    false → requestStoragePermissionAndPickFolder()
              if API >= 30 && !isExternalStorageManager():
                startActivityForResult(ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION)
              else if API < 30 && !hasPermission(WRITE_EXTERNAL_STORAGE):
                requestPermissions([READ,WRITE_EXTERNAL_STORAGE])
              else:
                openFolderPicker()
                  → startActivityForResult(ACTION_OPEN_DOCUMENT_TREE)
                    takePersistableUriPermission(treeUri, R|W)
                    path = uriToFilePath(treeUri)
                      // handles content://com.android.externalstorage.documents/tree/primary%3A...
                    tracker.setRootFolder(path)
                    tracker.ensureSubdirs()   (creates /track and /papers)
                    loadRandomBatch()

  onActivityResult():
    REQ_ALL_FILES  →  openFolderPicker()
    REQ_PICK_DIR   →  setRootFolder, ensureSubdirs, loadRandomBatch
    (cancellation falls back to suggestDefaultRoot() =
     Environment.DIRECTORY_DOCUMENTS/Papers)

11. CONFIGURABLE SCI-HUB DOMAIN
--------------------------------------------------------------------------------

Because sci-hub mirrors come and go, the user can swap the domain at any
time from the Settings tab. The setting is stored as a string with the
protocol stripped:

  TrackerStore.setDomain("https://sci-hub.se/")  →  "sci-hub.se"
  TrackerStore.getBaseUrl()                       →  "https://sci-hub.se"

On "Save domain" click, MainActivity rebuilds the SciHubClient:
  client = new SciHubClient(tracker.getBaseUrl())

All subsequent resolvePdf / fetchRelated calls hit the new domain.
The captcha solver code is unchanged — it works against any sci-hub
mirror that uses the altcha widget.

15. INSTALLATION
--------------------------------------------------------------------------------

Transfer Papers.apk to the Android device, then:

"Install unknown apps" permission for that file manager).

a folder. Until a folder is picked, no download or track operations
are available.
